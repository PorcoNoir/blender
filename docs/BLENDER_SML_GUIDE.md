# Blender-SML — User Guide

Blender-SML is a Blender fork that adds native node types for OMG **SysML v2**.
A SysML model is a first-class Blender node tree (`SysMLNodeTree`, peer to
Geometry / Shader / Compositor) that you can import from text, author in the node
editor, validate, round-trip to text, and **bind** to Blender's 3D scene
(geometry) and animation (armatures).

This guide covers each shipped capability with runnable steps. Reproducible
tutorial `.blend`s are generated by
`tools/sysml/make_tutorials.py` (see [Tutorials](#tutorials)).

---

## 1. The SysML node editor

- Open a **Node Editor**, set its type to **SysML** (the header tree-type
  selector), and create a new tree.
- **Add** menu (`Shift-A`) groups every SysML v2 element kind by family
  (Packages, Structure, Ports, Connections, Behavior, …).
- Elements wire through the **element reference socket**: an element's `Self`
  output plugs into another's typed inputs — `Members` (containment), `Type`
  (`of`), `Specializes`, `Redefines`, `Connect` / `To` (connectors).
- Per-element data lives on the node: `element_name`, `short_name`,
  `multiplicity`, `is_abstract`.

## 2. Import & export

- **Import**: `File ▸ Import ▸ SysML`, or `bpy.ops.node.sysml_import(filepath=…)`.
  Parses a `.sysml` file (via sml2c) into a new tree named after the file.
- **Export**: `bpy.ops.node.sysml_export(filepath=…, tree_name=…)` emits
  canonical `.sysml`. Export also targets a bpy graph-builder `.py`.

> sml2c (the SysML compiler) is fetched + pinned; see `tools/sysml/fetch_sml2c.py`
> and `extern/sml2c/sml2c.lock`. Import/validation need it; structural editing,
> serialization, and the bindings do not.

## 3. The SysML Text surface

Author SysML as text in Blender's **Text editor** and keep it in sync with the
graph on demand.

- **Text → Nodes**: `bpy.ops.node.sysml_text_to_nodes(text_name=…)` parses a
  Text datablock into a tree. An invalid model reports the sml2c diagnostic and
  creates no tree.
- **Nodes → Text**: `bpy.ops.node.sysml_nodes_to_text(tree_name=…)` writes the
  tree to a `<tree>.sysml` Text datablock.
- **Bind** a Text ↔ tree as two views: `bpy.ops.node.sysml_bind_text`. Then
  `bpy.ops.node.sysml_sync_to_text` / `…sync_from_text` update the bound partner.
  The binding survives `.blend` save/reload.

## 4. Validation & diagnostics

The **Diagnostics** panel (N-panel in the node editor) shows findings and a
**Validate** button (`bpy.ops.node.sysml_validate`). Two sources:

- **Local structural checks** (no sml2c): abstract definition instantiated
  (`B4001`), illegal reference-socket target (`B4002`), malformed multiplicity
  (`B4003`).
- **sml2c diagnostics**: the authoritative compiler findings on the exported
  text (`E0200` undefined name, …).

Offending nodes are badged (header colour); the panel lists each finding with a
jump-to-node button. Re-validating replaces markers; fixing a problem clears it.

## 5. Standard-library browser

The **Library** panel lists the resolvable standard packages — built-in
(`ScalarValues`, `Quantities`, `ISQ`, `SI`) and bundled (`ShapeItems`,
`SpatialItems`, `Time`, `Occurrences`). **Insert Library Type**
(`bpy.ops.node.sysml_insert_library_type`) adds an attribute typed by a chosen
`Package::Type` (e.g. `ISQ::LengthValue`) in one step.

## 6. Geometry binding — SysML ⇄ Blender objects

Map SysML `SpatialItem` shapes to native mesh objects.

- **Materialize** (graph → 3D): `bpy.ops.node.sysml_materialize` builds mesh
  primitives from shape parts (`Cuboid`, `Sphere`, `Cylinder`, `Cone`, `Torus`),
  applying dimensions (ISQ `[mm]` → scene units) and CSG (`differencesOf` →
  Boolean modifiers).
- **Reverse** (3D → graph): `bpy.ops.node.sysml_reverse` reads selected objects
  back into shape parts.
- **Live sync**: enable per tree with `bpy.ops.node.sysml_sync` (source of truth
  = Blender or Graph) so edits in one view flow to the other.

## 7. Animation binding — SysML ⇄ armatures & animation

- **Rig** (graph → armature): `bpy.ops.node.sysml_rig` builds one bone per
  bone-nature part; containment → bone parenting; connections → pose-bone
  constraints (IK / Copy-Transforms).
- **Keyframe**: `bpy.ops.node.sysml_animate` turns each part's `Occurrence`
  snapshots into pose keyframes (clock time → frame via the time↔frame bridge).
- **Behavior**: `bpy.ops.node.sysml_behavior` maps states → Blender Actions
  sequenced as NLA strips.
- **Capture** (armature → graph): `bpy.ops.node.sysml_capture` reads a hand-built
  rig + animation back into a SysML graph.
- **Live sync** + **methodology** (`Add Bone Chain`, `Build IK from Connection`,
  `Keyframe Pose`) mirror the geometry track.

## Tutorials

Generate the tutorial `.blend`s:

```bash
blender --background --factory-startup \
  --python tools/sysml/make_tutorials.py -- tutorials/
```

| File | Shows |
|---|---|
| `01_model.blend` | a structural model (parts, typing, containment) |
| `02_validation.blend` | a seeded defect, validated → node diagnostics |
| `03_geometry.blend` | a shape part materialised to a mesh object |
| `04_animation.blend` | a bone chain rigged into an armature |
| `05_library.blend` | an attribute typed from the standard-library browser |

Open any `.blend`, then explore its SysML tree (node editor) and the resulting
scene (3D viewport).
